# pi4-argon-one-m2-ubuntu-server

Встановлення захищеного **Ubuntu Server 24.04 LTS** на Raspberry Pi 4 з SSD у корпусі **Argon ONE M.2** одним скриптом.

Скрипт стирає SSD, ставить Ubuntu, створює твого користувача, підключає Wi-Fi (вибір зі списку мереж), вмикає захист, автовідновлення після збоїв, Docker і вентилятор Argon. Далі свої проєкти піднімаєш у Docker.

## Що налаштовується

- **Система:** Ubuntu Server 24.04 LTS (arm64) на M.2 SATA SSD, завантаження з USB першим.
- **Користувач і сервер:** твоє ім'я, пароль, hostname, часовий пояс. Стандартного користувача `ubuntu` немає.
- **Wi-Fi:** скрипт сканує мережі і показує список. Якщо Pi вже підключений до обраної мережі, пропонує взяти збережений пароль. Кабель теж працює, одночасно з Wi-Fi.
- **Безпека:**
  - UFW: вхідні закриті, SSH дозволено тільки з локальної мережі;
  - SSH: root заборонений, пароль приймається тільки з локальної мережі, інакше лише ключ;
  - fail2ban банить після 5 невдалих спроб, бан зростає до тижня;
  - автооновлення безпеки, захист мережі на рівні ядра.
- **Автовідновлення:**
  - апаратний watchdog перезавантажує Pi, якщо система зависла;
  - при kernel panic перезавантаження через 10 с;
  - fsck сам виправляє файлову систему після вимкнення світла;
  - журнал зберігається на диску.
- **Docker + Docker Compose.**
- **Вентилятор Argon ONE:** ставиться офіційний драйвер Argon40. Якщо він не працює на Ubuntu, при кожному старті автоматично вмикається вбудований запасний драйвер.
- **mDNS:** сервер доступний за адресою `hostname.local`.

## Що потрібно

- Raspberry Pi 4 з корпусом Argon ONE M.2 і M.2 SATA SSD.
- microSD з **Raspberry Pi OS Lite (64-bit)**, записана через Raspberry Pi Imager з увімкненим SSH.
- Інтернет на Pi (кабель або Wi-Fi).

## Встановлення

Завантаж Pi з microSD, підключись по SSH і виконай:

```bash
curl -fsSL https://raw.githubusercontent.com/vlad-tomiuk/pi4-argon-one-m2-ubuntu-server/main/install.sh -o install.sh
sudo bash install.sh
```

Скрипт усе спитає сам. Перед стиранням диска він покаже підсумок і попросить ввести `YES`.

### Параметри (необов'язково)

```bash
sudo bash install.sh -n my-server -u vlad          # задати hostname і користувача
sudo bash install.sh -n my-server -u vlad -w MyWiFi # і одразу Wi-Fi
sudo bash install.sh --no-wifi --no-docker          # тільки кабель, без Docker
sudo bash install.sh --help                         # усі параметри
```

| Параметр | Опис |
|---|---|
| `-n`, `--hostname` | ім'я сервера |
| `-u`, `--user` | ім'я користувача |
| `-w`, `--wifi` | Wi-Fi мережа (без цього скрипт покаже список) |
| `--no-wifi` | тільки кабель |
| `-c`, `--country` | країна для Wi-Fi (за замовчуванням `UA`) |
| `-t`, `--timezone` | часовий пояс (за замовчуванням `Europe/Kyiv`) |
| `--lan` | мережа, з якої дозволено SSH (визначається автоматично) |
| `--no-docker` | не ставити Docker |
| `--no-argon` | не ставити драйвер вентилятора |

### Паролі

Паролі не передаються параметрами, бо тоді їх видно в історії команд і в списку процесів. Якщо їх не вказати, скрипт спитає прихованим вводом. Для запуску однією командою є змінні середовища:

| Змінна | Опис |
|---|---|
| `SSH_PASSWORD` | пароль користувача (для входу по SSH і для `sudo`), мінімум 10 символів |
| `WIFI_PASSWORD` | пароль Wi-Fi, від 8 до 63 символів |

```bash
 sudo SSH_PASSWORD='MySecurePass123' WIFI_PASSWORD='wifipass123' bash install.sh -n server -u vlad -w 'HOME WiFi'
```

- Змінні пишуться **після** `sudo`, інакше `sudo` їх відкине.
- Пробіл на початку команди не дає їй потрапити в історію `history`.
- Паролі беруться в одинарні лапки `'...'`, щоб спецсимволи (`$`, `!`, `&`) не зіпсувались.
- Назву мережі з пробілами теж треба взяти в лапки.

### Після встановлення

1. `sudo reboot`. EEPROM оновиться, і Pi стартує з SSD.
2. Зачекай **10–20 хвилин**. Ставляться пакети, наприкінці Pi сам перезавантажиться ще раз.
3. Підключись: `ssh ТВІЙ_ЮЗЕР@HOSTNAME.local` (або по IP).
4. Перевір: `server-status` і `argon-fan-test`.
5. Вимкни Pi (`sudo poweroff`) і витягни microSD.

Лог встановлення: `/var/log/pi-setup.log`.

## Автовмикання після вимкнення світла

На платі Argon ONE (куди вставляється Pi) переставте перемичку живлення в режим **Always On**, зазвичай це положення 2-3. Інакше після зникнення живлення корпус чекатиме натискання кнопки.

## Команди на сервері

| Команда | Що робить |
|---|---|
| `server-status` | температура, мережа, файрвол, бани, вентилятор, контейнери |
| `server-update` | оновити систему |
| `argon-fan-test` | вентилятор на 100% на 5 секунд, щоб перевірити, що він працює |
| `passwd` | змінити пароль користувача |
| `sudo nano /etc/netplan/50-cloud-init.yaml`, потім `sudo netplan apply` | змінити Wi-Fi |

**Крива вентилятора:**
- офіційний драйвер: `argonone-config`;
- запасний: відредагуй `CURVE` у `/usr/local/bin/argon-fan`, потім `sudo systemctl restart argon-fan`.

## SSH-ключ (рекомендовано)

```bash
ssh-keygen -t ed25519
ssh-copy-id ТВІЙ_ЮЗЕР@HOSTNAME.local
```

## Docker і файрвол

Опубліковані порти Docker (`"8080:80"`) **обходять UFW**. Це нормально, поки на роутері не прокинуті порти. Сервіси, які мають бути доступні тільки на самому сервері (наприклад, за Cloudflare Tunnel), публікуй так: `"127.0.0.1:8080:80"`.
