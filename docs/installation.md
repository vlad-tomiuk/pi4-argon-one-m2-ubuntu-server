# Встановлення

Ubuntu Server 24.04 LTS на Raspberry Pi 4 з SSD у корпусі Argon ONE M.2 — однією командою.

## Що потрібно

- Raspberry Pi 4 (краще 4 або 8 ГБ) з корпусом **Argon ONE M.2** і M.2 SATA SSD;
- microSD з **Raspberry Pi OS Lite (64-bit)**, записана через Raspberry Pi Imager з увімкненим SSH;
- інтернет на Pi: кабель або Wi-Fi.

MicroSD потрібна лише для встановлення. Після нього її можна витягти або використати під бекапи
([docs/backups.md](backups.md)).

## Крок 1. Запустити встановлення

Завантаж Pi з microSD, підключись по SSH і виконай:

```bash
curl -fsSL https://raw.githubusercontent.com/vlad-tomiuk/pi4-argon-one-m2-ubuntu-server/main/install.sh -o install.sh
sudo bash install.sh
```

Скрипт спитає ім'я сервера, користувача, пароль, покаже список Wi-Fi мереж і визначить локальну
мережу для SSH. Перед стиранням SSD він виводить підсумок і чекає на слово `YES`.

### Параметри

```bash
sudo bash install.sh -n my-server -u vlad            # без питань про ім'я і користувача
sudo bash install.sh -n my-server -u vlad -w MyWiFi  # і одразу Wi-Fi
sudo bash install.sh --no-wifi --no-docker           # тільки кабель, без Docker
sudo bash install.sh --repo https://github.com/ти/твій-форк.git
sudo bash install.sh --help
```

| Параметр | Опис |
|---|---|
| `-n`, `--hostname` | ім'я сервера |
| `-u`, `--user` | ім'я користувача |
| `-w`, `--wifi` | Wi-Fi мережа (без цього скрипт покаже список) |
| `--no-wifi` | тільки кабель |
| `-c`, `--country` | країна для Wi-Fi (за замовчуванням `UA`) |
| `-t`, `--timezone` | часовий пояс (за замовчуванням `Europe/Kyiv`) |
| `--lan` | мережа, з якої дозволено SSH (визначається автоматично) |
| `--repo` | репозиторій з налаштуваннями — вкажи свій форк |
| `--no-docker` | не ставити Docker |
| `--no-argon` | не ставити драйвер вентилятора |

### Паролі

Паролі не передаються параметрами: вони були б видні в історії команд і в списку процесів.
Для запуску однією командою є змінні середовища:

```bash
 sudo SSH_PASSWORD='...' WIFI_PASSWORD='...' bash install.sh -n server -u vlad -w 'My WiFi'
```

- Змінні пишуться **після** `sudo`, інакше `sudo` їх відкине.
- Пробіл на початку рядка не дає команді потрапити в історію.
- Паролі беруться в одинарні лапки, щоб `$`, `!` і `&` не зіпсувались.

## Крок 2. Перезавантажити

```bash
sudo reboot
```

EEPROM уже налаштований на завантаження з USB, тому Pi стартує з SSD. Далі **10–20 хвилин**
працює `pi-setup.service`: ставить пакети, захист, Docker, драйвер вентилятора, команди сервера.
Наприкінці Pi перезавантажується ще раз сам.

Стежити за процесом: `sudo tail -f /var/log/pi-setup.log`

## Крок 3. Перевірити

```bash
ssh ТВІЙ_ЮЗЕР@ІМ_Я_СЕРВЕРА.local     # або за IP
server-status
argon-fan-test
```

Потім можна вимкнути Pi (`sudo poweroff`) і витягти microSD.

## Як це працює всередині

`install.sh` навмисно робить мало: стирає SSD, записує Ubuntu, пише cloud-init і ставить один
systemd-сервіс. Усе решта лежить у цьому репозиторії, який сервер клонує в `/opt/pi-server`
при першому старті і виконує [scripts/firstboot.sh](../scripts/firstboot.sh).

Завдяки цьому налаштування можна міняти без переустановлення системи:

```bash
server-update --self     # git pull + перевстановлення команд
```

Перший старт запускається через systemd, а не через cloud-init `runcmd`: `runcmd` виконується
рівно один раз і після раптового вимкнення живлення може залишитись порожнім — тоді сервер
залишається взагалі без налаштування і без захисту. Наш сервіс повторює спробу при кожному
завантаженні, поки не з'явиться `/opt/pi-setup/.done`.

## Автовмикання після зникнення світла

На платі Argon ONE переставте перемичку живлення в режим **Always On** (зазвичай положення 2-3).
Інакше після відновлення живлення корпус чекатиме натискання кнопки.
