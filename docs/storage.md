# Мережевий диск

Диск фіксованого розміру, який лежить на сервері й підключається до Windows як звичайна буква,
наприклад `W:`. Файли просто перетягуються в Провіднику.

Розмір обмежений самим образом: більше заданого в папку не запишеться, тож решта SSD
залишається вільною для Docker і сайтів.

```
Windows (W:)  ──SMB──▶  server:/srv/share  ──loop──▶  /srv/images/share.img (ext4, 10 ГБ)
```

## Налаштування на сервері

```bash
sudo bash /opt/pi-server/scripts/setup-share.sh
```

Скрипт створює образ, монтує його через `/etc/fstab`, ставить і налаштовує Samba, відкриває
порт 445 **тільки для локальної мережі** і просить задати пароль Samba (окремий від системного).

Заразом вимикає NetBIOS (порти 137/138) і протокол SMB1: вони потрібні лише клієнтам
часів Windows 98, а зайві відкриті порти — це зайва поверхня атаки. Перевірити, що слухає
сервер: `sudo server-status`, розділ «Підключення».

Свої параметри:

```bash
sudo bash scripts/setup-share.sh -s 50G -n Media -u vlad -m /srv/media
```

Повторний запуск безпечний: наявний образ, монтування і секція в `smb.conf` не чіпаються.

## Підключення у Windows

Найпростіше — скриптом [windows/Workplace-Disk.ps1](../windows/Workplace-Disk.ps1):

```powershell
powershell -ExecutionPolicy Bypass -File .\windows\Workplace-Disk.ps1 -Install
```

Він:

1. запитує пароль Samba один раз і кладе його в Диспетчер облікових даних Windows;
2. підключає диск як `W:`, а якщо буква зайнята — бере першу вільну з `V, U, T, S, R, Y, X`;
3. дає диску назву **Workplace** у Провіднику;
4. створює завдання в Планувальнику: перепідключення при вході і кожні 10 хвилин;
5. додає команду **`InitDisk`** у профіль PowerShell.

Параметри:

```powershell
.\Workplace-Disk.ps1 -Install -Letter V -Label "Сервер" -Share Workplace -User vlad -Server server
```

Вручну, без скрипта:

```powershell
net use W: \\server\Workplace /user:vlad /persistent:yes
```

macOS: `smb://server/Workplace`. Android/iOS: будь-який файловий менеджер з підтримкою SMB.

## Чому окремий скрипт, а не просто «Відновлювати при вході»

`/persistent:yes` відновлює диск лише під час входу в систему. Якщо сервер перезавантажився,
поки комп'ютер працював, диск залишається з червоним хрестиком. Завдання в Планувальнику
це підчищає: воно перевіряє диск і за потреби підключає заново, нічого не роблячи, якщо все гаразд.

Запускається воно через `wscript.exe` з прихованою обгорткою, інакше кожні 10 хвилин блимало б
вікно консолі.

Сервер не може підключити диск до ПК самостійно — SMB завжди монтує клієнт. Тому «драйвер»
для автопідключення — це і є завдання в Планувальнику.

## Перевірка

```bash
sudo disk-status
```

Показує, чи змонтований образ, скільки зайнято, чи працює Samba, чи відкритий порт, хто зараз
підключений, скільки файлів і що займає найбільше місця.

## Обслуговування

**Збільшити розмір** (наприклад, до 20 ГБ):

```bash
sudo umount /srv/share
sudo e2fsck -f /srv/images/share.img
sudo truncate -s 20G /srv/images/share.img
sudo resize2fs /srv/images/share.img
sudo mount -a
```

Зменшувати складніше: спершу `resize2fs` до меншого розміру, і лише потім `truncate`.
Переплутаний порядок знищує дані.

**Папка `lost+found`** — службова, туди `fsck` складає врятовані після збою файли. Видаляти її
не можна; від Windows вона прихована через `veto files` у `smb.conf`.

**Змінити пароль Samba:** `sudo smbpasswd -a vlad`

## Важливо

- Порт 445 **ніколи** не можна прокидати в інтернет. Для доступу ззовні — Tailscale
  ([docs/security.md](security.md)).
- Цей диск не є бекапом: він лежить на тому ж SSD, що й система.
- Якщо `server.local` не резолвиться з Windows — мережа має профіль **Public**, у якому
  блокується mDNS. Або перемкни профіль на Private, або звертайся на ім'я `server`
  (його видає DNS роутера) чи на IP.

## Видалити з Windows

```powershell
net use W: /delete
Unregister-ScheduledTask -TaskName "Workplace disk" -Confirm:$false
cmdkey /delete:server
```
