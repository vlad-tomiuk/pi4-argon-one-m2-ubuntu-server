# Команди сервера

Усі команди лежать у [bin/](../bin) і встановлюються в `/usr/local/bin` скриптом
[scripts/install-commands.sh](../scripts/install-commands.sh). Оформлення спільне —
бібліотека [bin/lib/ui.sh](../bin/lib/ui.sh).

Позначки в звітах: **✔** працює, **!** варто глянути, **✖** зламано. Смужки жовтіють
після 75% і червоніють після 90%.

## Огляд

| Команда | Що показує / робить |
|---|---|
| `server-status` | повний звіт по серверу: навантаження, диски, захист, підключення, контейнери |
| `disk-status` | мережевий диск: місце, хто підключений, вміст |
| `password-status` | менеджер паролів: контейнер, HTTPS, реєстрація, бекап |
| `bookmarks-status` | закладки: застосунок, база, HTTPS, скільки збережено, бекап |
| `server-update` | оновлює систему й контейнери |
| `argon-fan-test` | ганяє вентилятор на 100% 5 секунд |

## server-status

```bash
sudo server-status      # з sudo видно файрвол, бани fail2ban і деталі сесій
server-status -q        # мовчки, лише код повернення: 0 — все добре, 1 — проблема
```

Розділи звіту:

- **Шапка** — хост, версія Ubuntu, хто ввійшов і звідки, час роботи, кількість процесів.
- **Навантаження** — CPU у відсотках від усіх ядер, пам'ять за показником `available`
  (кеш не рахується зайнятим), swap, температура, історія просідань живлення
  (`vcgencmd get_throttled`). Недостатнє живлення — часта причина випадкових зависань Pi.
- **Диски** — кожен розділ зі смужкою, стан microSD, дерево `lsblk`.
- **Захист** — UFW, fail2ban, посилений SSH, автооновлення, потреба в перезавантаженні, Tailscale.
- **Підключення** — активні SSH-сесії і **порти, які слухають назовні**. Локальні (`127.0.0.1`)
  відфільтровані, тож видно справжню поверхню атаки.
- **Контейнери** — що працює, що зупинено.
- **Вентилятор** — який драйвер керує: офіційний чи запасний.
- **Корисні команди** — шпаргалка.

Код повернення робить команду придатною для моніторингу:

```bash
server-status -q || echo "щось зламалось" | mail -s "pi" ти@пошта
```

## disk-status

```bash
sudo disk-status        # з sudo показує, хто зараз підключений (smbstatus)
```

Змінні для нестандартного налаштування: `SHARE_MOUNT`, `SHARE_IMAGE`, `SHARE_NAME`.

## password-status

```bash
password-status
```

Читає з `.env` лише рядок `DOMAIN`; `ADMIN_TOKEN` не чіпає. Окремо перевіряє, що **реєстрація
закрита** — це легко забути після створення акаунта.

Змінні: `VAULTWARDEN_DIR` (типово `/srv/apps/vaultwarden`), `VAULTWARDEN_PORT` (типово `8080`).

## bookmarks-status

```bash
bookmarks-status
```

Показує адресу сайту, стан застосунку і PostgreSQL, HTTPS через Tailscale, чи закрита
реєстрація, кількість закладок, колекцій і тегів та розмір архівів сторінок.

Змінні: `LINKWARDEN_DIR` (типово `/srv/apps/linkwarden`), `LINKWARDEN_PORT` (типово `3000`).

## server-update

```bash
server-update           # система + образи всіх docker-compose проєктів у /srv/apps/*
server-update --self    # ще й git pull цього репозиторію та перевстановлення команд
```

## Що ще стоїть на сервері

Встановлення додає кілька стандартних утиліт з репозиторію Ubuntu:

| Команда | Для чого |
|---|---|
| `htop` | процеси, пам'ять і навантаження наживо |
| `mc` | двопанельний файловий менеджер (GNU Midnight Commander) |
| `tree` | структура папок деревом: `tree -L 2 /srv` |
| `sqlite3` | потрібен скриптам бекапу |

## Вентилятор Argon

```bash
argon-fan-test          # перевірити, що вентилятор взагалі крутиться
argonone-config         # крива офіційного драйвера
sudo systemctl status argononed argon-fan
```

Якщо офіційний драйвер Argon40 не працює на Ubuntu, при кожному старті вмикається запасний
контролер [bin/argon-fan](../bin/argon-fan) — це ~40 рядків Python, що керують вентилятором
через I2C. Його крива редагується прямо у файлі:

```python
CURVE = [(65, 100), (60, 55), (55, 30)]   # (°C, % обертів)
```

Потім `sudo systemctl restart argon-fan`.

За тим, що вентилятором хтось керує, стежить `argon-check.service` — він запускається при
кожному завантаженні й вмикає запасний драйвер, якщо офіційний не піднявся.

## Додати свою команду

1. Поклади файл у `bin/`, першим рядком — підключення спільного UI:

```bash
UI=${PI_UI:-/usr/local/lib/pi-server/ui.sh}
[ -r "$UI" ] || UI="$(dirname "$(readlink -f "$0")")/lib/ui.sh"
. "$UI"
```

2. Додай назву в список у [scripts/install-commands.sh](../scripts/install-commands.sh).
3. `sudo bash scripts/install-commands.sh`

Доступні функції: `title`, `section`, `row <ok|fail|warn|info> <мітка> <значення>`, `sub`,
`hr`, `bar <відсоток>`, `state_for <відсоток>`, `verdict <текст-ок> <текст-помилка>`.
