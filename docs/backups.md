# Бекапи

Система живе на SSD, а слот microSD у Pi вільний — туди й складаємо копії. Сенс простий:
копія на тому самому диску зникає разом із диском.

```
SSD (/dev/sda)                        microSD (/dev/mmcblk0)
├─ система, Docker, дані сервісів     └─ /srv/backup — тільки архіви
└─ /srv/share — мережевий диск
```

Карта ніяк не пов'язана із завантаженням: Pi стартує з SSD і працює без неї.

## Налаштування

```bash
sudo bash /opt/pi-server/scripts/setup-backup-sd.sh
```

Скрипт стирає карту (питає підтвердження), робить ext4, монтує її в `/srv/backup` за UUID з
опцією `nofail`, ставить `sqlite3` і створює розклад: щодня о 3:30.

Перевірка:

```bash
ls -lh /srv/backup/vaultwarden/
tail /var/log/vaultwarden-backup.log
server-status            # рядок «Бекапи» і стан microSD
```

## Що і як бекапиться

Скрипт [apps/vaultwarden/backup.sh](../apps/vaultwarden/backup.sh):

| Куди | Що | Скільки зберігається |
|---|---|---|
| `/srv/backup/vaultwarden` (microSD) | основні архіви | 90 днів |
| `/srv/share/backups/vaultwarden` (мережевий диск) | копії останніх | 7 штук |

В архів потрапляють база, ключі, вкладення, `docker-compose.yml` і `.env` — тобто відновлення
не потребує нічого ззовні. Кеш іконок пропускається.

Три деталі, які роблять його бекапом, а не видимістю:

- база копіюється через `sqlite3 .backup` — копія файлу «наживо» буває пошкодженою;
- архів одразу перевіряється через `gzip -t`;
- **якщо карта не змонтована, скрипт зупиняється з помилкою** і нічого не пише. Інакше архіви
  тихо лягали б на SSD, і ти дізнався б про це лише тоді, коли SSD помре.

Змінні для налаштування: `DST`, `MIRROR`, `KEEP_DAYS`.

## Відновлення

```bash
cd /srv/apps/vaultwarden
docker compose down
rm -rf data && mkdir data
tar -xzf /srv/backup/vaultwarden/vaultwarden-2026-09-20_0330.tar.gz -C data
mv data/docker-compose.yml data/.env . 2>/dev/null
docker compose up -d
```

Далі заходиш у сховище звичайним головним паролем.

## Чого цього замало

Карта лежить у тому самому Pi: пожежа, крадіжка чи залита водою плата знищують усе разом.
Тому потрібен ще один рівень — копія поза домом.

| Рівень | Від чого рятує |
|---|---|
| microSD у Pi | смерть SSD, пошкоджена база, випадкове видалення |
| Експорт у хмару чи на інший комп'ютер | втрата самого Pi |
| Головний пароль на папері | твоя пам'ять |

Найпростіший третій рівень для менеджера паролів — експорт з веб-інтерфейсу:
Tools → Export vault → **.json (Encrypted)**, з окремим паролем. Файл зашифрований, тож його
можна тримати в хмарі. Роби це раз на кілька місяців і після додавання важливих паролів.

## Наглядати за картою

SD-карти вмирають тихіше за диски. Раз на місяць:

```bash
df -h /srv/backup                       # чи є місце
ls -lt /srv/backup/vaultwarden | head   # чи свіжі архіви
sudo dmesg | grep -i mmc | tail         # помилки вводу-виводу
```

Порожній вивід останньої команди — добре. Помилки означають, що карту час міняти.

Раз на кілька місяців перевір, що архів справді розпаковується:

```bash
tar -tzf "$(ls -1t /srv/backup/vaultwarden/*.tar.gz | head -1)" | head
```

Бекап, який жодного разу не перевіряли, бекапом вважати не можна.

## Додати свій сервіс у бекап

Скопіюй `apps/vaultwarden/backup.sh` у папку свого сервісу, заміни шлях до даних і спосіб
зняття копії бази (для PostgreSQL — `pg_dump`, для файлів — просто `tar`), додай рядок у
`/etc/cron.d/`.
